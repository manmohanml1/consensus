# Milestone 0.3.0: Secure ephemeral rooms

## Outcome

Multiple anonymous participants can join a durable temporary room with correct authorization and lifecycle semantics.

## Work

- resolve ADR 0007 and provision the approved transactional store;
- schema, forward migrations, room capabilities, hashed tokens and expiry;
- locked roster, host recovery, indistinguishable unauthorized responses;
- idempotent command API and authorized projections;
- concurrency, authorization, migration, retention and deletion tests;
- threat-model review.

## Current status

Active. CQ-205 established the versioned provider-neutral room protocol. CQ-202 completed the portable room schema, role separation, checksum-protected forward migrations, and disposable PostgreSQL evidence. CQ-203 completed server-only capability issuance, keyed fingerprints, authorization, redaction, and cookie delivery. CQ-204/CQ-210 completed transactional command handlers with capability-authorized, privacy-minimized projections. CQ-206/CQ-213 completed the host creation boundary, random non-authoritative invitation locators, and anonymous abuse circuit breakers. CQ-207/CQ-211 completed pending admission, explicit host approval/removal, participant departure, immutable locked electorates, and concurrency evidence for duplicate lock/vote/resolve and expiry races. CQ-208/CQ-212 add authenticated terminal expiry, bounded aggregate deletion, and a guarded disposable database restore/teardown rehearsal. Shared Neon migrations, restore exercises, and teardown remain separately owner-gated.

## Exit gate

No client can modify another participant, duplicate commands are harmless, roster changes cannot silently alter a ballot, expired test rooms are deleted, and rollback/recovery is documented.
