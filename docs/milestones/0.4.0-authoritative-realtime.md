# Milestone 0.4.0: Authoritative realtime

## Outcome

Two to eight devices converge on committed room state under normal latency, duplicates, reordering and reconnects.

## Work

- compare/provision realtime transport;
- transactional outbox and publisher;
- client revision reconciliation and degraded polling;
- offline pending-state UX with bounded replay;
- network-partition simulator and multi-browser tests;
- latency/error dashboards and alert thresholds.

## Session-continuity preparation

The first client slice covers authorized reload, monotonic full-projection
reconciliation, bounded polling recovery and explicit identical-command retry.
It contributes to CQ-303, CQ-308, CQ-309 and CQ-310 without claiming their entire
transport-dependent acceptance criteria. The grouped implementation includes
unit invariants and isolated-browser tests for pending admission, ballot/result
reloads, denial, network failure, stale responses and uncertain delivery.
These browser tests mock API responses; they are not a new shared-Neon or
physical-device acceptance run. See [ADR 0016](../adr/0016-browser-room-session-continuity.md).

## Convergence foundation

The next grouped slice defines and parses the privacy-minimized v1 room-update
envelope, adds outbox lease/retry/poison/expiry mechanics, supplies a reusable
at-least-once publisher boundary, models current/reconciling/degraded/offline
client states, and runs seeded delay/loss/duplicate/reorder simulations in CI.
The connected-room UI exposes honest automatic-sync status while retaining the
confirmed projection during interruption.

This advances CQ-304, CQ-305, CQ-306, CQ-308, CQ-309, CQ-310, and CQ-311. It
does not close their provider-dependent or shared-environment criteria. CQ-301
provider selection, transport authorization, migration application, Preview
acceptance, and Production rollout remain separate owner gates. See
[ADR 0017](../adr/0017-provider-neutral-room-update-delivery.md).

## Full milestone exit

Automated tests prove no split-brain decision, no lost acknowledged vote, deterministic recovery after revision gaps, and visible degraded state.
