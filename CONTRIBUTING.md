# Contributing

Read `docs/PROJECT_GUIDE.md`, `AGENTS.md`, and the active milestone before editing.

## Flow

1. Branch from current `main` using `feat/`, `fix/`, `docs/`, `refactor/`, `perf/`, `test/`, `build/`, `ci/`, `chore/`, `release/`, `codex/`, or `dependabot/`.
2. Use a Conventional Commit pull-request title.
3. Keep the change inside one issue and milestone acceptance boundary.
4. Add focused tests, then run `pnpm verify`.
5. Include risk, recovery, screenshots for visual changes, and exact verification evidence.
6. Update repository records when product or architecture facts change.

Consequential provider, security, privacy, data, decision-rule, or deployment changes require an ADR before implementation.
